## Non-Obvious Conventions

### Plaid
- Always use the **cursor-based `/transactions/sync`** endpoint, not the deprecated `/transactions/get`
- Plaid `amount` is **positive for debits** (money out), negative for credits (money in) — matches our schema
- Access tokens must be **AES-256 encrypted** before writing to DB — use `TokenService.encrypt()`
- Plaid sandbox uses item ID `ins_109508` for Chase, `ins_3` for Wells Fargo (for tests)
- Webhook verification: validate `Plaid-Verification` header using Plaid's JWT verification

### GPT-4o Categorization
- Send transactions in **batches of 50 max** — larger batches hit context limits and inflate costs
- Use **structured output** (`response_format: { type: "json_object" }`) — never parse free-form text
- The system prompt lives in `src/api/services/CategoryService.ts` — don't split it across files
- GPT-4o can confuse transfers between own accounts as "income" — add special transfer detection logic

### Database
- All UUIDs generated by PostgreSQL (`gen_random_uuid()`), not the application
- Drizzle migrations live in `src/api/models/migrations/` — never edit them after running
- Use `db.transaction()` for any operation that writes to multiple tables
- Index on `transactions(user_id, date)` and `transactions(user_id, category)` — critical for analytics queries

### Auth
- Access token payload: `{ sub: userId, email, iat, exp }` — keep it minimal, no roles yet
- Refresh tokens stored as `sha256(token)` hash in DB, never raw
- Token family: when a refresh token is used, all tokens in the family are invalidated on replay detection

### React / Frontend
- API calls go through `src/web/lib/api.ts` — it handles token refresh automatically on 401
- Never call `fetch()` directly in components or hooks — always use the `api` client
- Chart data always lives in a custom hook (e.g., `useMonthlySpending`) — never in page components

### Testing
- Mock Plaid client in tests using `vi.mock('../services/PlaidService')` — never hit real Plaid in tests
- Mock OpenAI in tests — never hit real GPT-4o in tests (costs money + flaky)
- Use `tests/fixtures/` for reusable mock data (transactions, accounts, users)

## Common Gotchas

- Plaid webhooks require a publicly accessible URL — use `ngrok` in local dev
- `npm run db:migrate` must be run in `src/api/` package context, not root
- Vitest and Jest config conflict if both `jest.config` and `vitest.config` exist — use only Vitest
- React Plaid Link requires `react-plaid-link` package AND a valid Plaid Link token from backend
- GPT-4o `json_object` mode requires the word "JSON" to appear in the system prompt
